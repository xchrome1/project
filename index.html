CASE 01 · LIS · PRODUCTION INCIDENT

Results stuck in the validation queue on a live morning shift

T+0: ward reports results not printing. T+20m: queue isolated to the instrument-interface service — LIS core untouched. T+1h: mapping drift corrected, queue replayed in order. Same shift: ward confirms printout, incident closed with client sign-off.

Interface mapping had drifted from the analyzer's current output format, so valid results failed silent validation instead of raising an error. Classic "stuck, not crashed" — the worst kind, because nobody gets paged.

Added a loud-validation guard (reject + alert instead of silent hold), a replay runbook, and a regression case in the unit test plan. No recurrence since deploy.
